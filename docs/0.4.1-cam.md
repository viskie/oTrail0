# 0.4.1 — CAM host and preserved module state

CAM is downloaded separately, not bundled into the APK. The host adds only its camera permission, map/stop/settings entry points, generic module photo API and normalized photo index. The recorder, route rendering and map provider implementations are unchanged. A v3→v4 additive migration creates `photos` plus indexes; existing journal tables/IDs are retained.

APK updates use the same application ID and signing certificate. No update path clears module packages, prior versions, activation, settings, sources, drafts or private data. Each module's data directory is keyed by its module ID, independent of its installed version. Activation markers are atomic and read across processes so the map icon follows CAM activation. GOD 1.0.0 and 1.0.1 remain separately selectable/rollbackable; the installation password is unchanged. GOD 1.0.1 lays out landscape actions and navigation tabs in three columns.

CAM opens inside oTraiL with Camera2 controls, stop-linked photo albums and in-app photo viewing/reverse stop lookup. Original JPEGs and JSON recovery sidecars are saved in Downloads/oTraiL/Photos or the selected folder before indexing. A failed index insertion does not delete originals. Rebuilding the index repairs changed content URIs and resolves stop association against restored trail data. Stale fixes retain their original fix time; unconfirmed stops remain unassigned. See modules/mod2/README.md.

Photo originals require their own folder backup; existing trail-only backup format is unchanged. App uninstall differs from update: folder access must be re-granted and the photo index rebuilt after a reinstall. Private module data is retained by in-place upgrades, not guaranteed after uninstall/clear storage.
