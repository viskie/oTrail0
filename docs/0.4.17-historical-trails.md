# 0.4.17 — historical journeys and map details

Menu → Historical trails accepts 2–100 places per list and up to 20 UTF-8 CSV/text files per batch. Examples:

    Delhi, Jaipur, Agra

Or CSV (optional order/time columns):

    order,name,lat,lon,time
    1,Delhi,28.6,77.2,2020-01-01
    2,Agra,27.17,78.04,2020-01-02

Explicit order wins; otherwise complete timestamps establish chronological order, otherwise input order is retained. Coordinates must be in India. Cities resolve via the phone geocoder, cached locally; ambiguous results require review. Coordinate input works without geocoding. The selected offline engine needs matching graph tiles; online driving routes use the configured endpoint. Fastest car routes generally favour major highways but connectors remain necessary. No straight-line fallback is used.

Build a preview, inspect resolved places/distance or View on map, then Review pending previews → Approve merge. Multiple approved journeys are bright yellow. Each can be hidden, edited, re-routed, reloaded from its original file or removed. Replacing an existing journey requires another approval; its old geometry remains until then. Hidden journeys still contribute to Total. Failed previews leave approved data intact. Imported route distances are estimates; they never become GPS fixes or current-drive distance. Raw source text, chronology, resolved waypoints, route geometry, visibility, IDs and distance persist separately in an atomic versioned journal. Trail backup now includes that journal and merges IDs on restore.

India offline roads use hierarchy-dependent widths, optional source lane tags and existing palette/casings. Unknown lane data falls back to road class. Major roads receive source ref labels at suitable zoom levels. These theme changes do not change navigation/trail styling or baked online raster tiles. Two-finger rotation is available outside WTF mode. Religious places, including the orange title, align left.

GPS requests are 1 second with movement or poor accuracy, 13 seconds stationary, and 30 seconds after 10 minutes stopped only when significant-motion wake-up is available. Motion wakes 1-second requests. Actual fix delivery depends on hardware/reception. Traffic-jam grouping is conservative: two observed stop/go cycles can hold one stop episode during slow movement within 600 m. Sustained free flow or leaving that corridor ends it. Long parking stops and uncertain fixes retain existing safeguards. Raw observations remain unchanged; stop duration is reconstructed from evidence rather than invented GPS points.

Build, 111 unit tests and lint passed. Existing data, module installation and manual fonts/colours are retained; no uninstall or data reset.
