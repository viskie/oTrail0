# oTraiL 0.2.3 — implementation and upgrade guide

This update implements the supplied stop-geocoding guide and the additional requests for nearby historic places, sequential marker popups, the entire collected trail, and coloured gap connections. It keeps inferred connections in logs only, with no estimate label on the map and no fabricated GPS fixes.

## 1. Safeguard the existing journal

Before modifying source, the existing commit was preserved as branch `backup-before-stop-geocoding`; the original Java directory was copied outside the repository. The user's untracked `android-project-sources.txt` is not part of the change.

A raw pre-upgrade archive of the installed app's database, WAL, and preferences was saved on the phone at `Download/oTraiL/pre-geocoding-backup-2026-11-05.tar` (refreshed immediately before deployment; the November 4 archive is also retained). The initial capture checked that database/WAL hashes stayed unchanged during copying. This is an emergency developer archive, **not** a JSON file for the app's Restore button. Normal Google Drive/Files snapshots remain the supported in-app restore format. Do not uninstall to upgrade.

Migration and backup tests are run in an independently installed `in.otrail.validation` application before upgrading `in.otrail`. Test databases are also isolated in device-protected storage; production continues collecting GPS during validation.

## 2. `app/src/main/java/in/otrail/TrailDb.java`

1. Advance SQLite helper version from 1 to 2. Keep `trails.db`, application identity, old tables, IDs and units.
2. Fresh databases add `place_name`, `locality`, `district`, `state`, `country`, `postal_code`, `road`, `geocode_status` (default `PENDING`) and `geocode_attempt_ms` (default 0) to stops.
3. Upgrade v1 using `ALTER TABLE ... ADD COLUMN` only for stop records. No table is dropped or journal row rewritten. Compare trip/fix/stop counts before/after and append a migration audit to logs.
4. Index the geocoding queue; add an index on global fix time and a derived historic-place cache. A partial unique log index prevents duplicate inferred-gap log entries.
5. Expose stable stop IDs and address/status fields through `Stop`. `stopById` reads one stop directly instead of loading a trip.
6. Return `-1` from `record` for ordinary fixes and the inserted stop ID when a new >2-minute stop is confirmed. StopDetector behavior is unchanged.
7. Add `pendingStopIds`, `saveStopAddress` and `markGeocodeFailed`. Failed lookups are eligible again after 24 hours. Failed/in-flight lookups cannot overwrite an already-resolved address.
8. `fixes(-1)` and `stops(-1)` return all collected journeys chronologically. A selected positive trip ID still filters one journey.
9. Store display-inference details in deduplicated `sync_logs` entries. Never insert inferred samples into `fixes` or change measured coordinates/timestamps.
10. Extend GeoJSON stop properties with stable ID and address/status fields; fix export and `[longitude, latitude]` ordering remain intact. Export `schema_version` remains 1 with additive optional fields.
11. Snapshots already serialize all stop columns. Backup format version stays 1; old backups omit the new columns and receive database defaults. Duplicate-stop restore fills only missing address fields, preserves existing names and timings, and may promote an unresolved stop to `RESOLVED`. Existing transactional rollback and trip-ID remapping remain.

## 3. `app/src/main/java/in/otrail/StopGeocoder.java` — new

1. Keep a single throttled coordinator independent of UI, GPS writing, cloud backup and historic-site fetching.
2. Read eligible stops from SQLite; resolve one at a time, about one per second plus lookup time. Continue draining historical stops beyond the first batch; coalesce repeated backfill requests.
3. Use Android Geocoder's asynchronous API on API 33+. Wait at most 15 seconds on this background worker.
4. On API 30–32, contain the synchronous call in a bounded single-thread executor with a 15-second wait. If a legacy binder call ignores interruption, it occupies at most that one legacy thread rather than spawning replacements indefinitely.
5. Save place/locality/district/state/country/PIN/road when available. Null/empty responses, unavailable services, errors and timeouts become `FAILED`; coordinates are unchanged.
6. Never hold a SQLite transaction open across a lookup. Empty Address objects are not incorrectly marked resolved.

Android's Geocoder may be absent, inaccurate, incomplete or network-dependent. There is no embedded offline address database. See [Android Geocoder](https://developer.android.com/reference/android/location/Geocoder).

## 4. `app/src/main/java/in/otrail/TrackingService.java`

1. Backfill at initial service startup and wake eligible retries hourly; newly confirmed stop IDs also wake the queue.
2. Move GPS writes onto a dedicated serial executor so a cloud backup upload cannot occupy the GPS writer. Geocoding uses its own executor.
3. Keep the 5,000 ms GPS request, zero minimum distance, GPS provider, persistent notification, permission checks, START_STICKY and reboot/update recovery.
4. Shut down workers in order and close their shared database only after queued GPS/backup work finishes.

Geocoding has no path that stops the service or ends a journey. Location delivery still depends on Android, permissions and GPS reception.

## 5. `app/src/main/java/in/otrail/MainActivity.java`

1. Load the entire journal for the default Live view; History offers “Entire collected trail” and individual journeys.
2. Fit the initial viewport to the entire collected trail. Locate returns to the current position and can request a fresh fix even while recording.
3. Render stop popup title from place name, with locality, road, district, state, country, PIN, arrival, observed duration, departure/last observation and coordinates. Unresolved locations remain selectable.
4. Include all Stop record fields in the display signature. An address update refreshes the marker even without a new GPS fix.
5. Use stable marker keys; close the previous popup before binding a clicked marker. Preserve the selected popup across periodic redraws and close it on a blank-map tap.
6. Draw gap connections in amber with no text label or inference popup, as requested. Keep the inference details only in logs.
7. Add “Identify historical stop locations” in Maps & downloads. It respects the 24-hour failure cooldown.
8. Add “Old places” with find/refresh, cached display and hide options. Search uses a recent GPS position within India and a 25 km radius, not an arbitrary map pan position. The offline-only switch blocks refresh but permits cached results.
9. Show up to 50 nearest matching places as gold name labels on every basemap; popup includes source date, age range/approximation when present in the source, cache time and an OSM source link. Historic-place age descriptions are separate from trail-gap rendering.
10. Send historic network requests on their own executor so they do not delay GPS writing or map refresh.

## 6. `app/src/main/java/in/otrail/MarkerPopups.java` — new

Centralize the one-popup-at-a-time policy so it can be exercised directly by a device regression test, including A → B → A clicks. The activity manages stable ownership across map redraws.

## 7. `app/src/main/java/in/otrail/TrailSegments.java` — new

1. Consume recorded samples in chronological order, across all journeys.
2. Keep observed runs separate at a recording gap or journey boundary. Preserve the first/last sample of every run when thinning displayed points.
3. Add a separate straight-line display edge only for gaps of at most 30 minutes, at most 60 km, and plausible implied speed at most 60 m/s. Long or implausible gaps stay disconnected.
4. Keep the recorded and inferred edge types separate. Only the renderer uses the amber edges; export and backups contain measured GPS points, not a guessed route.

This does not infer the road taken or perform map matching. There is insufficient evidence to recreate a driven route from two endpoints alone.

## 8. `app/src/main/java/in/otrail/HistoricAge.java` — new

Parse OSM year/date values, explicitly approximate years, century tags and closed year ranges. At the current UTC year, accept only source date ranges wholly within the requested 200–600 year age window. Unknown dates, open-ended dates and unsupported expressions are not assigned an invented age.

## 9. `app/src/main/java/in/otrail/HistoricPlaces.java` — new

1. Request named historic/heritage/tourism elements with `start_date` from the public Overpass service, on demand, within 25 km of the phone's recent fix.
2. Enforce India bounds, request/read timeouts, a 300-element query cap and a 4 MB response cap. Reject partial/error responses while retaining existing cache.
3. Normalize source type/ID, name, coordinates, original date, year range, uncertainty and fetch time into SQLite.
4. Filter by source date and actual distance. Return nearest cached sites offline; no geocoding or GPS dependency for reading the cache.

Coverage depends on OSM tags and public server availability. Age tags are not independently authenticated; an empty result means no matching dated data was returned, not that no old places exist. Map data/caches stay on the phone. See [OSM start_date](https://wiki.openstreetmap.org/wiki/Key:start_date) and [Overpass query language](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL).

## 10. Tests

`app/src/androidTest/java/in/otrail/BackupInstrumentation.java` has 14 checks:

1. Upgrade a genuine v1 database while preserving IDs, coordinates, timestamps, foreign keys and logs.
2. Restore a v1 JSON backup with default pending address fields.
3. Preserve addresses in snapshots.
4. Include addresses and correct coordinate order in GeoJSON.
5. Roll back a truncated snapshot.
6. Restore enriched stop fields.
7. Merge enrichment into unresolved duplicates without duplicating GPS rows.
8. Preserve an existing name while filling missing address fields.
9. Confirm stop ID return and allow GPS writes during a deliberately blocked lookup.
10. Handle lookup failure and enforce/release the 24-hour cooldown.
11. Drain more than 25 historical stops.
12. Filter/cache historic source dates and reject distant results.
13. Record inferred edges only once in logs, without adding GPS fixes.
14. Open popups A → B → A with only the selected marker's window open.

`TrailSegmentsTest.java` adds four JVM tests for endpoint retention, short-gap connections, implausible/long-gap rejection and journey separation. `HistoricAgeTest.java` adds four date/age parsing tests. The six existing StopDetector tests remain unchanged: 14 JVM tests total. Tests use fake addresses, never a live geocoder response.

## 11. `app/build.gradle`

Keep normal application ID `in.otrail`, SDK 30/35 and dependencies. Increment to versionCode 5 / versionName 0.2.3. The `-PvalidationBuild` switch changes only the validation installation ID to `in.otrail.validation`, preventing test upgrades from touching production data.

## 12. Build and upgrade sequence

```sh
. /src/android-build-env/environment.sh
./gradlew -PvalidationBuild testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w in.otrail.validation.test/in.otrail.BackupInstrumentation

# Only after validation succeeds, build the real application:
./gradlew testDebugUnitTest lintDebug assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n in.otrail/.MainActivity
```

The real update uses the existing debug signing identity and `adb install -r`. No uninstall, data clear, map deletion or permission reset is part of deployment. APK snapshots and checksums go in the repository's `releases/` folder, not GitHub Releases. Live geocoder/provider availability and long-duration battery behavior remain distinct from deterministic automated checks.
