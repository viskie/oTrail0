# 0.2.6 — continuity, history and offline routing

- Confirmed dwell detection resumes from persisted stops, including stops closed by older collector versions. Recovery walks actual stationary observations backwards across sessions/restored trips and keeps the earliest supported arrival; recorded movement or leaving the anchored radius ends that search. Changes to recovered arrival are logged. No GPS fixes are created or deleted.
- Plausible gaps between recorded observations are connected in green, without UI labels. Connections are estimates and recorded only in inference logs; they are not road-matched or proof of the actual path. Impossible speeds remain disconnected.
- History now loads journey summaries off the main thread instead of loading every journey's GPS samples into the picker. Map recreation releases the previous map/provider. Trail fitting waits for layout and expands zero-width/height bounds; rendering failures are logged and contained.
- Settings independently selects online OSRM, embedded BRouter, or embedded native Valhalla. Offline choices support new routes and rerouting with offline-only enabled. Offline destinations can be selected by holding the map or entering coordinates. Name search still requires internet. No voice guidance.
- BRouter runtime source is vendored at the revision recorded in third_party/brouter/UPSTREAM.md. Car-vario routing rules and lookup dictionary are bundled; geographic .rd5 files are downloaded only onto the phone from BRouter's public segments4 service. Choose every regional tile crossed by the route.
- Valhalla Mobile 0.6.4 is included through Maven Central, using Valhalla 3.9.0. A compatible prepared India graph archive is required. There is no verified public India graph URL preconfigured: settings supports a user-supplied HTTPS download URL, optional publisher SHA-256, and retained .tar import. The existing .map/.osm.pbf files cannot substitute for this graph. Engine integration is implemented; out-of-box India Valhalla data provisioning remains dependent on that source.
- Downloads allow Wi-Fi and cellular, display bytes/progress/status, and retain originals in shared Downloads/oTraiL. Import retained routing files after reinstall. Checksummed BRouter validation and Valhalla tar structural validation run off the UI thread. An installed graph is replaced atomically only after validation; downloads/imports never write the trail database.
- Install this signed update over the existing app. Database version remains 2 and signing identity is unchanged. Android uninstall still removes private data: restore a configured trail snapshot and import retained map/routing downloads after reinstall. No update can recover already deleted, unbacked-up observations.

Validation: 34 JVM tests pass, Android lint has no errors, app and instrumentation APKs build. The restart recovery instrumentation check compiles but has not run: no phone is connected. Both offline engines are packaged, but real India graph routing and the reported history crash still need phone verification. No geographic dataset is in the APK or repository.
