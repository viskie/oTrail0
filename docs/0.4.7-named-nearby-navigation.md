# 0.4.7 — narrow GPS bubble and named nearby destinations

The GPS bubble is 132dp wide (about 40% narrower than the ~218dp measured live popup on the POCO), with uniform 11sp text and no extra container padding. Its border increases from 1dp to 4dp; text sits against the inner edge. Worship information moves entirely into the side-panel results box, including each nearest mapped site's name and straight-line distance. Missing site names/coverage are stated rather than invented.

The same dataset request includes the nearest mapped police station. The side panel lists it alongside Hindu, Muslim, Christian, Sikh and Buddhist sites within 25 km in any direction. The fetched area has an extra 5 km movement buffer. Old caches are recognized as not yet searched for police and refreshed rather than falsely reporting no station. Refresh/fallback retains existing data.

Mapped named entries are underlined/clickable. They open a confirmation with the destination coordinates and current destination before calculating and automatically starting the new route. Roadside landmarks and saved stops offer the same navigation path; historic markers retain navigation access. An explicit new destination supersedes an in-flight recalculation. A failed request restores the prior usable route. Cancel does not replace the current destination; clearing navigation clears pending automatic starts.

Navigation history is a separate persistent SQLite database, independent of the GPS journal. It records route/destination summaries on Start and before successful replacement, and preserves the current route when first viewed. Identical route summaries are deduplicated with last-use timestamps; old entries are not purged. Open it from the left navigation menu and confirm a destination to calculate a fresh route from the current GPS position. Existing map/provider/offline-routing selections apply.

No GPS journal migration or collector changes. Existing modules, maps, preferences, trail data and photo index are retained.

Validation: assembleDebug, testDebugUnitTest (90 checks), and lintDebug passed. On-device isolated instrumentation passed journal preservation, CAM migration, recovery, stale GPS and navigation-history persistence. Confirm/cancel and history listing were checked on the POCO. The live police refresh had not completed before ADB disconnected; existing worship cache remains available and the police row correctly shows pending refresh.
