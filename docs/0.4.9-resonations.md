# 0.4.9 — Resonations

A compact native player sits directly above the bottom-right total/status panel in landscape and above total statistics in portrait. Files opens Android's multi-select document picker. Choosing a new set replaces the saved playlist; cancelling leaves it intact. The box shows up to three filenames and a fourth “…” line if more were selected. Files can also come from a compatible document provider; local recordings work offline. No audio is packaged into the app or copied into the trail database.

MP3, audio in MP4/M4A, AMR/3GP, AAC, WAV, OGG/Opus and FLAC recordings use Android's installed codecs. A corrupt, inaccessible or unsupported file is skipped; if none can play, the player stops with a visible error rather than retrying indefinitely. MP4 playback uses its audio without opening a video UI. No recording button or microphone permission is added.

Play loops the entire selected list in order, wrapping from last to first; a one-file list repeats that file. Pause retains the track and position. Clear stops audio and removes the playlist references. Persisted document read permissions and a separate `resonations` preference file preserve selection across app restart and normal upgrades. Original files are never deleted. Media playback is a separate user-started foreground service with notification/lock-screen pause controls and audio focus, independent of the GPS recorder. Screen-off playback holds a playback wake lock; a call or competing audio focus pauses it. Selection is remembered after reboot, but playback only starts when requested.

Typography/color tokens and button labels are configurable in UiConfig. No changes to journal schema, stop detection, offline maps, routing or module data.

Android references: https://developer.android.com/media/platform/supported-formats and https://developer.android.com/media/optimize/audio-focus . Actual format support depends on the codec inside the selected container and device support.

Validation: assembleDebug, 95 JVM tests and lintDebug passed. Playlist tests cover persisted round-trip, three visible filenames, overflow fourth line, loop boundaries, malformed data, duplicate references and non-document rejection. Phone absent from ADB: picker interaction, actual audio codecs and screen-off playback are not yet device-verified.
