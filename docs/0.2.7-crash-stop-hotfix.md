# 0.2.7 — map crash and stop display hotfix

Device crash logs identified a destroyed osmdroid map repository being reused to construct trail/navigation polylines. MapView automatically destroys its repository on window detachment; the app also explicitly owns teardown and reparents the map during screen changes. The app now disables automatic destroy-on-detach and removes the old view before exactly one explicit teardown. This applies to all three basemaps.

Stop details now open in independent Android dialogs, with a Stops list on the main screen so details remain accessible independently of map drawing and shared popup state. A private last-crash report captures uncaught Java failures and Android process exit reasons; Maps & downloads can display/copy it. It never edits the trail database.

The phone database passed SQLite integrity checks before installation: 35,592 fixes and 42 stops, including one open stop. A pre-update database/preferences archive was saved on the phone in the app's private files/pre-0.2.7-trails-backup.tar. Subsequent recording continues to add observations. No stops were deleted by this hotfix.

Observed GPS jitter around 35–38 metres, at 0–1.18 m/s, was closing otherwise confirmed stops at the old fixed radius. Confirmed stops now account for reported accuracy and require sustained departure evidence; large, clear departures remain immediate. Pending stops retain their original anchored dwell rules. Recovery uses the same accuracy tolerance. A regression test covers the actual boundary-jitter pattern.

Validation: 35 JVM checks and Android lint pass. Device instrumentation includes map reparent/repository survival, unchanged stop title/snippet, earliest-arrival recovery, backup integrity and non-destructive migration. Real full history, individual history, return to Live and independent stop details were exercised on the connected POCO with its existing data. Installed in place with the existing signing key; database schema unchanged.
